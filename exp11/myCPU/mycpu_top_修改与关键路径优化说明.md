## 2. 具体修改

下表行号均对应当前版本，便于定位。

| 位置 | 修改前 | 修改后 | 作用 |
| --- | --- | --- | --- |
| 第 260 行 | 没有分支专用操作数信号 | 新增两个 32 位 wire：`ds_br_rj_value`、`ds_br_rkd_value` | 将分支数据选择与通用操作数选择分开；没有增加寄存器 |
| 第 485～490 行 | 分支共用 `rj_value`、`rkd_value` 的 EX/MEM/WB/RF 选择通路 | 新增说明注释及两组 MEM/WB/RF 选择逻辑 | 分支数据输入中不再包含 `es_exec_result` |
| 第 491 行 | `rj_eq_rd = (rj_value == rkd_value)` | 比较 `ds_br_rj_value` 与 `ds_br_rkd_value` | 缩短 `beq/bne` 的操作数到判定路径 |
| 第 499～500 行 | `jirl` 目标使用 `rj_value + jirl_offs` | 改用 `ds_br_rj_value + jirl_offs` | 从间接跳转地址计算中移除 EX 结果输入 |

### 2.1 新增分支专用前递

```verilog
wire [31:0] ds_br_rj_value, ds_br_rkd_value;

assign ds_br_rj_value = ds_rj_fwd_ms ? ms_final_result :
                        ds_rj_fwd_ws ? ws_final_result : rf_rdata1;
assign ds_br_rkd_value = ds_rkd_fwd_ms ? ms_final_result :
                         ds_rkd_fwd_ws ? ws_final_result : rf_rdata2;
assign rj_eq_rd = (ds_br_rj_value == ds_br_rkd_value);
```

通用操作数 `rj_value/rkd_value` 仍然按照 **EX > MEM > WB > RF** 选择；新分支操作数按照 **MEM > WB > RF** 选择，复用原有的 MEM/WB 前递控制信号。

这里改变的是数据来源，不是另外实现一套 RAW 检测，也不是把分支改到 MEM 级执行。分支仍然在 ID 级判定，只在依赖 EX 生产者时等待其结果进入 MEM。

### 2.2 修改 jirl 的基址来源

```verilog
assign ds_br_target = (inst_beq || inst_bne || inst_bl || inst_b)
                   ? (ds_pc + br_offs)
                   : (ds_br_rj_value + jirl_offs);
```

PC 相对分支仍然使用 `ds_pc + br_offs`。只有 `jirl` 的寄存器基址换成分支专用操作数，偏移计算和链接值写回均未修改。

## 3. 如何优化关键路径

### 3.1 修改前：控制上禁用 EX 分支前递，结构上仍共用数据选择器

两份代码原本都有以下条件：

```verilog
assign ds_rj_fwd_es = ds_rj_raw_es && es_result_available
                   && !ds_is_reg_branch;
assign ds_branch_ex_stall = ds_is_reg_branch
                        && (ds_rj_raw_es || ds_rkd_raw_es);
```

因此，`beq/bne/jirl` 在功能上已经不使用 EX 前递；但是旧版的比较器和目标地址加法器仍连接到通用 `rj_value/rkd_value`，而这些信号的选择器包含 `es_exec_result`。

旧 RTL 存在以下结构连接（表示潜在组合时序路径，不表示分支在功能上允许当拍消费 EX 结果）：

```text
EX 操作数寄存器
  → ALU / 组合乘法器
  → es_exec_result 结果选择
  → 通用 EX/MEM/WB/RF 操作数选择
  ├→ beq/bne 比较 → 分支条件 → PC 选择
  └→ jirl 目标地址加法 → PC 选择
  → nextpc → fs_pc 寄存器 / 指令 RAM 地址及内部译码
```

代码中乘法 IP 要求 `PipeStages=0`，其组合运算延迟可能较大。如果综合后保留上述连接，EX 运算、前递选择和分支逻辑就可能串联在一个周期内。功能上的暂停或互斥条件，并不保证综合器一定消除所有结构路径，也不代表静态时序分析必然忽略它们。

### 3.2 修改后：直接移除分支选择器的 EX 数据输入

新结构为：

```text
MEM 结果 / WB 结果 / 寄存器堆
  → 分支专用 MEM/WB/RF 选择
  ├→ beq/bne 比较 → 分支条件 → PC 选择
  └→ jirl 目标地址加法 → PC 选择
  → nextpc → fs_pc 寄存器 / 指令 RAM 地址及内部译码

EX 执行结果
  → 通用操作数选择 → 普通指令的 ID/EX 寄存器
  → EX/MEM 结果寄存器
```

对于 ALU、乘法等非 load 结果，分支使用 MEM 前递时，数据已经经过 `ms_alu_result` 寄存器。因此 EX 运算和后续分支计算被既有的 EX/MEM 寄存器分隔，不再通过这两处分支数据输入串成一条组合链。load 的 MEM 前递则来自 `data_sram_rdata`，仍有存储器返回数据到分支的路径。

这个优化有三点价值：

1. **去掉多余数据连接。** 不依赖综合器从分支类型、前递使能和暂停条件中推导 EX 数据不可用于有效跳转。
2. **简化分支数据选择。** 从四类候选数据减少为三类；最终 LUT 数和逻辑层数由综合映射决定，不能仅凭 RTL 宣称固定减少一层。
3. **减少共享数据通路的负载。** EX 结果不再通过原通用选择输出承担分支比较和间接跳转的数据用途，可能改善扇出与布局布线；具体收益需要报告验证。

这里没有新增流水级，也没有修改乘法器、除法器或 ALU 本身。新增 wire 不强制物理布局隔离，综合器仍可合并逻辑；准确含义是 RTL 层面分离数据选择并移除直接 EX 数据输入。EX 目的寄存器、有效位及除法完成信号等控制信息仍可影响分支暂停和跳转使能。

## 4. 为什么不会增加停顿或取到旧数据

### 4.1 EX 相关分支原本就要等到 MEM

现有控制链为：

```text
分支读取 EX 将写回的寄存器
  → ds_branch_ex_stall = 1
  → ds_raw_stall = 1
  → ds_ready_go = 0
  → ds_to_es_valid = 0
  → br_taken_cancel = 0
```

即使等待期间分支专用选择器退回寄存器堆、得到暂时过期的值，也不会触发有效跳转。待最新生产者进入 MEM，分支才用 MEM 前递值判定。

以 `mul.w r5, r6, r7` 后紧跟读取 `r5` 的 `beq` 为例：

| 周期 | 生产者 | 消费者 | 修改前后共同的行为 |
| --- | --- | --- | --- |
| N | 乘法在 EX | 分支在 ID | 检测 EX 相关，分支暂停、不重定向 |
| N+1 | 乘法结果在 MEM | 分支仍在 ID | 使用 MEM 前递结果比较，在允许离开 ID 时决定跳转 |

在当前流水线条件下，普通 ALU/乘法生产者对应这一拍等待；多周期除法则要等待其完成并进入 MEM，不能统一描述为只停一拍。这些等待条件此次均未改变。

### 4.2 最新写者优先规则不变

```verilog
assign ds_rj_fwd_ms = ds_rj_raw_ms && !ds_rj_raw_es;
assign ds_rj_fwd_ws = ds_rj_raw_ws && !ds_rj_raw_es && !ds_rj_raw_ms;
```

`rkd` 使用相同规则。如果 EX 和 MEM/WB 同时写同一寄存器，EX 对应更新的值，MEM/WB 的旧值被屏蔽，ID 分支继续等待。若没有 EX 相关，则优先选 MEM，其次 WB，最后寄存器堆。寄存器零、无效槽和非写回指令的过滤也维持原状。

### 4.3 普通指令仍可使用 EX 前递

`ds_alu_src1/ds_alu_src2` 仍使用原来的 `rj_value/rkd_value`，store 数据也仍从 `rkd_value` 进入 `es_rkd_value`。因此不会为了缩短分支路径而让普通相关运算统一多等一拍。分支冲刷、PC 相对目标、`bl/jirl` 链接写回、访存接口和 debug 写回接口均未修改。

报告显示已指定的时序约束得到满足，但同时记录了 15 个输入端口缺少 input delay、71 个输出端口缺少 output delay，因此不能把这一结果扩展为所有外部接口时序均已验证。也不能将 `1/17.995 ns` 直接作为设计最高频率，时钟偏斜、不确定性及建立时间等仍需计入。

## 6. 验证范围与总结

本文完成了两份 RTL 的逐行对比、分支前递与暂停条件核对、修改前截图与修改后报告的汇总指标对比，以及修改后时序报告的路径检查；没有重新运行仿真、综合或布局布线，也不把代码分析等同于形式等价验证。

本次优化利用了原本就存在的“分支依赖 EX 时暂停，进入 MEM 后再前递”规则，将分支所用的数据选择从通用旁路中分离出来。在保持原有流水级数和暂停策略的同时，移除了 EX 执行结果到分支比较和 `jirl` 目标计算的直接数据通路。结合修改前截图，WNS 从 −0.584 ns 提高到 +0.998 ns，改善 1.582 ns；TNS 从 −30.289 ns 清零，144 个建立时间违例端点全部消除。修改后报告明确显示 CPU 在 50 MHz 约束下通过时序检查。上述数据支持时序收敛改善的结论，但具体路径延迟变化和最高频率提升仍需同一约束和实现条件下的完整前后报告验证。
